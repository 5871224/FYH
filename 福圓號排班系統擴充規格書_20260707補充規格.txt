# 一、設定頁共同拖曳排序規則

## 1.1 適用頁面

下列設定頁的資料列，最前方必須統一顯示拖曳排序圖示：

1. 人員設定。
2. 單位設定。
3. 班別設定。
4. 假別設定。
5. 加班設定。
6. 訂餐品項設定。

## 1.2 操作方式

1. 只有最前方拖曳圖示可以開始拖曳。
2. 點擊或拖曳資料列其他欄位，不得觸發排序。
3. 拖曳過程必須顯示插入位置提示。
4. 放開後立即更新畫面順序。
5. 排序結果必須保存，重新整理或重新登入後仍維持原順序。
6. 人員排序必須同步套用於班表的人員顯示順序。

## 1.3 拖曳欄版面

1. 拖曳欄統一放在表格最前方。
2. 電腦版拖曳欄寬度為約 30px，屬於「接近最小但仍容易操作」的寬度。
3. 拖曳圖示可視範圍約為 22px × 26px。
4. 拖曳欄不得擠壓主要資料欄位或造成操作欄超出頁面。

---

# 二、人員設定排序

## 2.1 人員排序保存

1. 人員設定頁允許主管及管理員以拖曳方式調整人員順序。
2. 排序值保存於人員資料的排序欄位。
3. 新增人員時，預設排在現有人員之後。
4. 讀取人員資料時，優先依保存的排序值顯示；排序值相同時，再依工號及識別值穩定排序。
5. 排序操作不得修改人員的單位、角色、班別、到職日或其他資料。

---

# 三、訂餐設定頁版面與排序

## 3.1 品項表格版面

1. 品項名稱欄寬度必須適度縮小，讓價格、啟用及操作欄完整顯示在頁面內。
2. 操作欄不得超出訂餐設定頁右側。
3. 表格應使用固定欄寬配置，品項名稱輸入框可在剩餘空間內縮放。
4. 電腦版及手機版都不得因品項名稱過長造成操作按鈕離開可視範圍。

## 3.2 品項拖曳

1. 品項最前方顯示拖曳圖示。
2. 只有拖曳圖示可調整品項順序。
3. 在品項名稱、價格、啟用勾選或操作按鈕上拖曳時，不得改變排序。

---

# 四、加班審核頁

## 4.1 表格欄位版面

1. 最前方勾選欄左右需保留少量空間，不得緊貼表格邊界。
2. 日期欄左右需保留少量空間，日期及警告文字不得擠在一起。
3. 狀態欄應縮小至足以顯示「待審」、「核准」及「退回」的寬度。
4. 操作欄可換行排列「調整」、「核准」及「退回」按鈕，不得超出表格。

## 4.2 調整功能

管理員按下「調整」時，必須可以修改：

1. 提早上班加班時數。
2. 延後下班加班時數。
3. 員工加班備註。

儲存規則：

1. 時數仍須為 0.5 小時的倍數。
2. 時數不得為負數。
3. 修改後的備註必須寫回原加班申請。
4. 使用「儲存為待審」時，狀態回到待審並保存修改後的時數及備註。

---

# 五、個人記錄頁

## 5.1 顯示欄位

個人記錄頁依序顯示：

1. 日期。
2. 圖示。
3. 班別。
4. 打卡時間。
5. 異常。
6. 加班。
7. 打卡備註。
8. 加班備註。
9. 訂餐。

個人記錄頁不再顯示「操作」欄。

## 5.2 圖示欄

1. 圖示欄必須直接重現班表頁同一天的班表格內容。
2. 顏色、文字顏色、圓角、字級及分段方式必須與班表一致。
3. 同一天同時存在班別、假別或加班時，依以下順序上下疊加：
   1. 班別。
   2. 假別。
   3. 加班。
4. 最多顯示三個分段。
5. `0047 休息日` 與班別同時存在時，文字顏色沿用班表的灰色顯示規則。
6. 沒有班別、假別及加班時，圖示格保持空白，不顯示虛構資料。

## 5.3 打卡時間欄

原「上班」及「下班」兩欄合併為單一「打卡時間」欄。

顯示格式：

```text
07:58 莊敬
11:25 莊敬
```

規則：

1. 第一行顯示上班打卡時間及打卡單位。
2. 第二行顯示下班打卡時間及打卡單位。
3. 缺少其中一筆時，該行顯示 `-`。
4. 時間以 Asia/Taipei 時區顯示。

# 六、打卡頁今日狀態

## 6.1 進入頁面時讀取

1. 手機、平板及電腦進入打卡頁時，都必須立即向後端讀取伺服器判定的今日打卡資料。
2. 不得只依賴瀏覽器本機快取或先前頁面狀態。
3. 今日日期必須由後端以 Asia/Taipei 判定。
4. 電腦版與手機版必須讀取相同的今日打卡資料來源。

## 6.2 已打卡資訊

今日已有上班或下班打卡時，頁面必須顯示：

1. 打卡時間。
2. 打卡單位。
3. 打卡來源，例如 GPS 或 IP。

例如：

```text
07:58在莊敬打卡(IP)
```

## 6.3 按鈕狀態

1. 已完成上班打卡後，「上班打卡」按鈕不可再次操作。
2. 已完成下班打卡後，「下班打卡」按鈕不可再次操作。
3. 已完成下班打卡時，上班及下班按鈕都不得重複送出。
4. 讀取今日狀態失敗時，需顯示錯誤訊息，不得把已有打卡誤顯示成尚未打卡。

## 6.4 後端讀取方式

今日打卡狀態應透過受身分驗證的打卡後端服務讀取，回傳安全欄位：

```text
record
serverDate
profile
```

前端不得因電腦版使用不同的瀏覽器儲存區而讀不到今日紀錄。

# 七、實作及資料保存補充

1. 人員排序使用持久化排序欄位保存。
2. 人員排序 API 僅允許主管及管理員寫入。
3. 個人記錄後端需讀取 `schedule_entries` 的班別、假別及加班類型，並回傳組合圖示所需資料。
4. 加班審核後端需允許管理員更新原申請的員工備註。
5. 今日打卡狀態讀取需使用與打卡寫入相同的受驗證後端服務，避免裝置差異造成資料不一致。

---

# 八、驗收條件

## 8.1 電腦版打卡

1. 先用手機完成上班打卡。
2. 使用同一帳號在電腦登入。
3. 進入打卡頁。
4. 電腦頁面應立即顯示手機完成的上班時間、單位及來源。
5. 上班按鈕應為不可操作狀態。

## 8.2 個人記錄圖示

1. 班表同一天設定班別、假別及加班。
2. 進入個人記錄頁查詢該日期。
3. 圖示欄應與班表相同順序上下疊加三段。
4. 每段顏色及文字顏色應與班表一致。

## 8.3 設定頁拖曳

1. 人員、單位、班別、假別、加班及訂餐品項最前方都有拖曳圖示。
2. 只有拖曳圖示能改變順序。
3. 重新整理後順序仍保留。
4. 拖曳欄約 30px，不得造成其他欄位溢出。

## 8.4 加班審核

1. 調整視窗可同時修改提早時數、延後時數及備註。
2. 儲存後重新查詢，修改後備註仍存在。
3. 狀態欄縮窄後仍能完整顯示狀態文字。
