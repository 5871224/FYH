# 第一章　打卡頁

## 1.1 頁面目的

打卡頁用來讓已登入人員完成當日上班與下班打卡、查看伺服器判定的今日日期、今日班別與已完成的打卡資訊，並在符合條件時提出打卡加班申請。

本頁以手機操作為優先，但手機、平板與電腦必須讀取同一筆正式打卡資料。進入頁面時一律重新向受身分驗證的後端讀取今日狀態，不依賴瀏覽器快取或先前畫面狀態。

## 1.2 分頁與功能區

本頁目前沒有傳統頁籤，分為兩個功能區：

1. **今日打卡：** 顯示今日日期、班別、上班及下班打卡狀態並提供打卡按鈕。
2. **加班申請：** 以「加班申請」勾選框展開，顯示當日加班資格、申請時數、備註與申請狀態。

### 1.2.1 今日打卡

#### A. 按鈕使用說明

1. **上班打卡**
   - 按下後先顯示確認視窗。
   - 確認後才取得手機定位或送出電腦 IP 驗證。
   - 第一次成功時間為正式時間。
   - 已有上班時間後按鈕停用。
   - 已有下班時間時，上班按鈕也維持停用。

2. **下班打卡**
   - 按下後先顯示確認視窗。
   - 沒有上班時間時仍可下班打卡。
   - 第一次成功時間為正式時間。
   - 已有下班時間後按鈕停用。

3. **返回首頁**
   - 使用 X 圖示。
   - 顯示在姓名右側並靠右對齊。
   - 返回登入後首頁，不登出。

#### B. 顯示欄位與格式

1. 使用者姓名。
2. 伺服器判定的今日日期。
3. 今日班別名稱。
4. 今日班別上下班時間。
5. 上班打卡時間、單位與來源。
6. 下班打卡時間、單位與來源。
7. 讀取或打卡失敗訊息。

已打卡狀態顯示在按鈕內，例如：

```text
07:58在莊敬打卡(IP)
```

來源只使用：

```text
GPS
IP
管理員補登
```

#### C. 核心邏輯

1. 正式日期與時間由後端以 `Asia/Taipei` 判定。
2. 電腦版進入頁面時，透過 `attendance-clock` Edge Function、`action: today` 讀取今日資料。
3. 手機、平板與電腦都讀取同一個 `attendance_records` 正式來源。
4. 每人每天最多一個上班時間與一個下班時間。
5. 快速連按、網路重送或重複請求不得覆寫第一次成功時間。
6. 沒有排班仍可打卡。
7. 有請假資料仍可打卡。
8. 員工可在任何已啟用打卡的公司單位打卡；地點與班別適用單位不同時，打卡仍成立並列為異常。
9. 手機驗證順序：
   - 先取得 GPS。
   - GPS 距離公司地點不超過 300 公尺，且定位精準度不超過 300 公尺時，以 GPS 打卡。
   - GPS 拒絕、失敗、逾時、距離不符或精準度不符時，改驗證固定對外 IP。
   - 多個地點符合時，選擇距離最近的單位。
   - 前端定位等待上限至少 15 秒。
10. 電腦與平板：
    - 不要求 GPS。
    - 不呼叫瀏覽器定位。
    - 只驗證固定對外 IP。
11. 讀取今日狀態失敗時顯示錯誤，不把已有紀錄誤顯示為尚未打卡。
12. 單位日後改名、搬家或調整座標，不回寫歷史打卡快照。

#### D. 權限

- **員工：** 可查看自己的今日班別與打卡狀態，可完成自己的上班及下班打卡。
- **主管：** 具備員工全部能力。
- **管理員：** 具備主管全部能力，並可在紀錄頁的打卡管理分頁補登、修改或清除打卡資料與查看修改歷程。

### 1.2.2 加班申請

#### A. 按鈕與控制項

1. **加班申請勾選框**
   - 預設只顯示勾選框。
   - 勾選後才載入完整加班申請區塊。

2. **提早上班時數**
   - 以 0.5 小時為單位。
   - 預設帶入系統計算值。

3. **延後下班時數**
   - 以 0.5 小時為單位。
   - 預設帶入系統計算值。

4. **加班備註**
   - 可填寫原因或補充說明。
   - 與每日打卡備註、訂餐品項備註分開保存。

5. **送出加班申請**
   - 驗證時數與申請期限後建立待審申請。

6. **刪除申請**
   - 待審或退回狀態可刪除。
   - 刪除後在期限內可重新申請。
   - 採邏輯刪除並保留歷程。

#### B. 申請條件與計算

1. 有有效上班時間。
2. 有有效下班時間。
3. 當日有可計算的班別。
4. 班別有完整上下班時間。
5. 提早上班或延後下班至少 30 分鐘。
6. 尚在工作日期後 5 個日曆天內。
7. 同一天沒有其他有效申請。
8. 計算規則：
   - 各自向下取 0.5 小時單位。
   - 未滿 30 分鐘不計。
   - 提早與延後分開計算後加總。
9. 員工送出前可調高或調低系統計算值。
10. 每一欄不得為負數，必須是 0.5 的倍數。
11. 合計為 0 時系統拒絕送出。
12. 送出後由刪除並重提的流程重新申請。
13. 下班打卡完成後，若系統計算可申請時數至少 0.5 小時，主動詢問是否申請並帶入時數。
14. 狀態：
    - `pending`：待審。
    - `approved`：核准。
    - `returned`：退回。
15. 打卡加班申請與班表格中的加班設定是兩套獨立資料，不互相同步。
16. 管理員修改當日打卡後，既有申請回到待審並顯示「打卡時間已異動」，原申請時數不自動重算。
17. 已送出的申請不因班表、班別時間或班別適用單位後續變更而自動改變。

#### C. 權限

- **員工：** 可查看自己的申請資格、送出申請、查看狀態，並在期限內刪除待審或退回申請後重新申請。
- **主管：** 具備員工全部能力。
- **管理員：** 具備主管全部能力，並可在紀錄頁審核、調整、批次處理或代為建立申請。

## 1.3 其他相關規則

### 1.3.1 打卡異常

異常依最新班表、班別設定、班別適用單位與目前有效打卡資料即時計算，不永久固定結果。

時間只比較到分鐘，忽略秒數：

- 09:00:59 相對 09:00 不算遲到。
- 09:01:00 相對 09:00 算遲到。
- 17:59:59 相對 18:00 算早退。

同一天可同時出現：

1. 未打上班。
2. 未打下班。
3. 遲到。
4. 早退。
5. 無排班但有打卡。
6. 上班時間晚於下班時間。
7. 打卡時間不完整或格式異常。
8. 上班地點不符。
9. 下班地點不符。
10. 班別缺少完整上下班時間。

### 1.3.2 單位打卡設定

每個單位保存：

- 單位名稱。
- 開始日期。
- 結束日期。
- 班表隱藏狀態。
- 地址。
- 緯度。
- 經度。
- 固定對外 IP。
- 是否啟用打卡。

停用單位打卡後，該單位立即停止 GPS 與 IP 匹配；歷史打卡維持不變。

### 1.3.3 管理員異動後的員工按鈕

1. 當日 23:59 前：
   - 清除上班時間且尚無下班時間時，上班按鈕可重新啟用。
   - 清除上班時間但已有下班時間時，由管理員補登。
   - 清除下班時間時，下班按鈕可重新啟用。
2. 當日 23:59 後：
   - 員工按鈕不重新啟用。
   - 後續由管理員補登或修改。
3. 清除採作廢或軟刪除概念，修改歷程永久保留。

# 第二章　訂餐頁

## 2.1 頁面目的

訂餐頁用來處理當日員工餐點下訂、主管與管理員的訂餐統計，以及商品、截止時間與公司補助設定。正式訂單以當日上班打卡單位為訂餐單位快照。

## 2.2 分頁

1. **今日訂餐：** 員工選擇品項、數量及各品項備註。
2. **訂餐統計：** 主管與管理員依條件查詢明細、品項與人員彙總並匯出 Excel。
3. **訂餐設定：** 主管與管理員管理商品、截止時間、公司補助與品項順序。

### 2.2.1 今日訂餐

#### A. 按鈕與欄位

1. **品項**
   - 顯示目前啟用商品。
   - 已訂購後才停用的商品仍保留在該員工畫面。

2. **價格**
   - 顯示商品目前適用價格。

3. **數量**
   - 只接受 0 或正整數。
   - 負數、小數、科學記號與其他非整數內容在輸入當下拒絕。
   - 停用品項最多保留原訂數量，只能減少或歸零。

4. **備註**
   - 每個品項各自保存一份備註。
   - 不使用整張訂單共用備註取代品項備註。

5. **儲存訂餐**
   - 新增或更新今日整張訂單。
   - 顯示即時計算的總份數與總金額。

6. **取消整張訂單**
   - 已有訂單且所有數量改成 0 時，顯示確認視窗。
   - 確認後刪除該訂單全部品項，不建立取消狀態。

7. **返回首頁**
   - 使用 X 圖示返回首頁。

#### B. 訂餐資格與邏輯

1. 今日已有有效上班打卡。
2. 上班打卡有明確單位。
3. 送出時尚未超過伺服器判定的每日截止時間。
4. 只處理今天，不處理未來日期。
5. 不要求今日有班表。
6. 請假或打卡地點與班別適用單位不同，不阻止訂餐。
7. 第一次下訂時全部數量為 0，系統不建立訂單。
8. 同一位員工同一天只有一個 `order_id`，不同商品各一列。
9. 修改訂單：
   - 維持原 `order_id`。
   - 維持第一次下訂時間 `submitted_at`。
   - 維持第一次訂餐單位快照。
   - 更新品項、數量、備註與最後修改時間。
10. 截止後停止新增、修改與取消。
11. 管理員補登當日上班卡後，符合截止時間時可訂餐。
12. 訂餐完成後管理員若清除上班卡，訂單保留並在個人記錄及統計備註顯示警告。
13. 商品停用後：
    - 尚未訂購者不再顯示。
    - 已訂購者仍顯示名稱與原數量。
    - 可減少或取消，不可增加。
14. 歷史訂單保存下訂時商品名稱、單價、員工與單位快照。

#### C. 權限

- **員工：** 可查看可訂商品、建立自己的今日訂單、在截止前修改或取消自己的今日訂單。
- **主管：** 具備員工全部能力。
- **管理員：** 具備主管全部能力。

### 2.2.2 訂餐統計

#### A. 查詢欄位與按鈕

1. 日期起日。
2. 日期迄日。
3. 單位。
4. 員工。
5. 報表類型：
   - 明細。
   - 品項。
   - 人員。
6. 日期、單位或員工條件變更後，立即重新查詢並更新統計結果。
7. 報表類型變更後，立即切換顯示內容。
8. **匯出**：依目前篩選條件匯出 Excel。
9. 上一頁、下一頁與筆數資訊。
10. 明細預設每頁 50 筆。
11. 預設日期為今天。
12. 本分頁不顯示查詢按鈕。

#### B. 報表欄位與邏輯

1. **明細**
   - 日期。
   - 訂餐單位。
   - 員工姓名。
   - 品項。
   - 數量。
   - 單價。
   - 小計。
   - 備註。
   - 上班打卡已被清除等警告併入備註，不另設警告欄。
   - 不顯示員工工號、第一次下訂時間與最後修改時間。

2. **品項**
   - 品項。
   - 數量。
   - 單價。
   - 小計。

3. **人員**
   - 姓名。
   - 訂餐日數。
   - 金額。
   - 自付額。

自付額：

```text
金額 -（訂餐日數 × 公司補助）
```

4. 頁面顯示期間總數量與期間總金額。
5. Excel 匯出使用單一「訂餐統計」工作表，每位員工一列。
6. 匯出欄位依序為：
   - 員工姓名：員工姓名。
   - 員工編號：員工工號。
   - 早餐金額：空白。
   - 午餐金額：依頁面相同公式計算的自付額。
   - 晚餐金額：空白。
   - 早餐份數：空白。
   - 午餐份數：訂餐日數，同一員工同一天不重複計算。
   - 晚餐份數：空白。
   - 總計：空白。
   - 日期：使用訂餐統計查詢條件的結束日期，格式為 `YYYYMMDD`。
7. 匯出內容依目前日期、單位及員工篩選條件產生。

#### C. 權限

- **員工：** 可使用今日訂餐功能。
- **主管：** 具備員工全部能力，並可查詢訂餐統計與匯出 Excel。
- **管理員：** 具備主管全部能力。

### 2.2.3 訂餐設定

#### A. 按鈕與欄位

1. **截止時間**
   - 全系統共用每日截止時間。
   - 預設 `10:30`。

2. **公司補助**
   - 全系統共用。
   - 預設 55。
   - 只接受大於 0 的正整數。

3. **新增商品**
   - 新增一筆空白商品列。

4. **儲存**
   - 儲存截止時間、公司補助、商品內容及排序。

5. **拖曳排序**
   - 每列最前方顯示拖曳圖示。
   - 只有圖示可開始拖曳。
   - 品項名稱、價格、啟用欄與操作按鈕不觸發拖曳。

6. **刪除**
   - 新增後尚未儲存的空白列直接移除。
   - 沒有任何歷史訂餐記錄的商品，在確認後可刪除。
   - 已有歷史訂餐記錄時，後端拒絕實體刪除並提示改用停用。

7. 商品欄位：
   - 品項名稱。
   - 價格。
   - 是否啟用。
   - 排序。
   - 操作。

#### B. 欄位與版面規則

1. 商品名稱不可重複。
2. 價格可為 0，且不得為負數。
3. 品項表格使用固定欄寬。
4. 品項名稱欄使用剩餘寬度。
5. 價格、啟用與操作欄必須完整留在頁面內。
6. 拖曳欄目前約 42px，圖示操作範圍約 28px；其他設定頁的共用拖曳欄約 30px。
7. 電腦與手機版都需避免操作欄超出可視範圍。
8. 截止時間修改後立即生效：
   - 延後且尚在新截止時間內時重新開放。
   - 提前且已超過新時間時立即關閉。
9. 截止前修改商品價格時，今日包含該商品的訂單以交易方式同步更新單價與小計。
10. 截止後修改價格不影響已截止今日訂單與歷史訂單。

#### C. 權限

- **員工：** 可使用今日訂餐。
- **主管：** 具備員工全部能力，並可新增、修改、排序、啟用、停用與刪除符合條件的商品，可修改截止時間與公司補助。
- **管理員：** 具備主管全部能力。

## 2.3 其他相關規則

1. 正式商品資料：`meal_products`。
2. 正式設定資料：`meal_settings`。
3. 正式訂餐資料：`meal_orders`。
4. 不建立訂單主檔；同日多項商品共用同一個 `order_id`。
5. 唯一識別原則：`user_id + order_date + product_id`。
6. 訂單總數量與總金額查詢時計算，不另存主檔總額。
7. 訂餐儲存、整張取消、價格同步更新必須使用後端交易或 RPC。
8. 重複送出相同訂單請求必須具有冪等性。

# 第三章　班表頁

## 3.1 頁面目的

班表頁用來顯示完整八週班表，讓所有已登入角色查看班別、假別與班表加班；主管與管理員另可編輯班表、設定單位與人員、維護班別／假別／加班／國定假日、執行例休檢查與自動排班。

## 3.2 檢視分頁

班表檢視下拉選單包含：

1. 人員檢視。
2. 人員檢視－統計欄。
3. 班別檢視。

### 3.2.1 人員檢視

#### A. 顯示欄位

1. 單位。
2. 人員。
3. 八週日期欄。
4. 每日格可同時顯示：
   - 班別。
   - 假別。
   - 班表加班。
5. 分段順序固定為班別、假別、加班。
6. 顏色、文字顏色與圓角依各設定項目顯示。
7. 今日欄位需有明顯標示。
8. 未在職日期顯示為不可排班格。

#### B. 按鈕與操作

1. 前八週、前一週、後一週、後八週。
2. 頂端與表格左右的週次導覽。
3. 單位顯示範圍篩選。
4. 工具列中的班別、假別、加班選擇。
5. 點選格子套用目前選擇項目。
6. 取消班別、取消假別、取消加班。
7. 多格拖曳選取。
8. 複製、剪下、貼上、刪除。
9. 復原與重做。
10. 雙擊人員或單位進入編輯。
11. 拖曳單位及同單位內人員調整班表顯示順序。

#### C. 邏輯

1. 每人每天最多一個班別。
2. 不處理跨日夜班、一天多班與一天多次上下班。
3. 一個班表格以 `member_id + work_date` 唯一識別。
4. 班別、假別與班表加班保存在同一列 `schedule_entries`。
5. 空白格不保留無內容資料列。
6. 班別適用單位是單選且必填。
7. 假別可保存整天或起迄時間與原因。
8. 班表加班可保存起迄時間、兩段休息與原因。
9. 班表加班與打卡加班申請彼此獨立。
10. 手機版頂端控制列允許換行，不因單行擠壓造成水平溢出。

#### D. 權限

- **員工：** 可查看所有人員完整班表。
- **主管：** 具備員工全部能力，並可編輯班表、調整顯示順序及使用排班工具。
- **管理員：** 具備主管全部能力。

### 3.2.2 人員檢視－統計欄

#### A. 作用

在「人員檢視」全部功能上，額外顯示每位人員於目前範圍的統計欄，協助檢查班數、休假或排班配置。

#### B. 操作與邏輯

1. 排班格操作與人員檢視相同。
2. 統計依目前已載入的八週班表即時計算。
3. 變更班表後同步更新統計。
4. 統計欄只作顯示，不是獨立資料來源。

#### C. 權限

- **員工：** 可查看完整班表與統計欄。
- **主管：** 具備員工全部能力，並可編輯班表。
- **管理員：** 具備主管全部能力。

### 3.2.3 班別檢視

#### A. 作用與欄位

1. 以班別為列。
2. 顯示每日已排人員。
3. 顯示班別需求人數。
4. 顯示人數不足提示。
5. 依班別適用單位與營運日期判斷是否顯示。

#### B. 操作與邏輯

1. 主要用途是檢查各班別每日人力。
2. 此檢視以查看為主，排班編輯回到人員檢視操作。
3. 需求人數來自 `set_shift.required_staff_count`。
4. 當日排班人數低於需求時顯示缺員狀態。

#### C. 權限

- **員工：** 可查看班別人力配置。
- **主管：** 具備員工全部能力。
- **管理員：** 具備主管全部能力。

## 3.3 設定、工具與其他規則

### 3.3.1 共用工具列

1. 班別、假別、加班項目以彩色按鈕顯示。
2. 可依單位篩選班別。
3. 工具列可收合。
4. 浮動工具列右上角顯示「上一步」與「下一步」SVG 圖示按鈕。
5. 「上一步」對應 `Ctrl+Z`，「下一步」對應 `Ctrl+Y`，使用相同的班表操作歷程。
6. 沒有可復原或重做的操作時，對應按鈕停用。
7. 最多保留最近 20 次班表操作歷程；執行新的班表修改後清除下一步歷程。
8. 復原或重做後，立即更新畫面並同步保存變更的班表格。
9. 隱藏於工具列的設定項目仍保留歷史班表顯示。
10. 按 `Esc` 可取消目前選取的排班工具。
11. 「匯出休例假」、「匯出請假」及「匯出加班」按下後，先顯示日期範圍選擇視窗，再依選定期間匯出。
12. 日期範圍視窗包含開始日期、結束日期、取消與對應的匯出按鈕。
13. 日期範圍視窗的左右寬度與「自動排班期間」視窗相同。
14. 日期範圍視窗不顯示預設期間說明框。
15. 匯出前會重新載入選定期間的正式班表資料，不受目前班表畫面顯示的八週範圍限制。
16. 匯出檔名包含選定的開始日期與結束日期。

### 3.3.2 單位設定

欄位：

- 單位名稱。
- 開始日期。
- 結束日期。
- 是否從班表隱藏。
- 排序。
- 地址。
- 緯度。
- 經度。
- 固定對外 IP。
- 是否啟用打卡。

按鈕與操作：

- 新增、編輯、刪除。
- 匯入、匯出。
- 最前方拖曳排序圖示。
- 拖曳欄約 30px，只有圖示可開始拖曳。

邏輯：

1. 有人員、班別、打卡或訂餐歷史引用的單位由後端保護歷史關聯。
2. 一個單位保存一組目前打卡設定。
3. 主管寫入一般欄位時，前端與後端會排除打卡敏感欄位。

權限：

- **員工：** 可在班表與相關頁面查看必要的非敏感單位名稱。
- **主管：** 具備員工全部能力，並可管理單位名稱、有效日期、班表隱藏與排序。
- **管理員：** 具備主管全部能力，並可設定地址、座標、固定 IP 與打卡啟用狀態。

### 3.3.3 人員設定

欄位：

- 工號。
- 姓名。
- 所屬單位。
- 角色。
- 到職日。

- 日薪人員。
- 固定休假星期。
- 每月休假天數。
- 可支援單位順序。
- 可排班班別順序。

按鈕與操作：

- 新增、編輯、刪除。
- 重設密碼。
- 匯入、匯出。
- 篩選姓名、單位、角色、在職狀態與薪資類型。
- 最前方拖曳排序圖示。
- 拖曳排序同步影響班表人員顯示順序並永久保存。

權限：

- **員工：** 可查看班表中的人員名稱與必要資訊。
- **主管：** 具備員工全部能力，並可建立員工帳號、維護員工與主管的非角色資料、重設員工與主管密碼，以及刪除符合條件的員工或主管帳號。
- **管理員：** 具備主管全部能力，並可建立員工、主管與管理員，修改角色及管理管理員帳號。

帳號刪除規則：

1. 有班表、打卡、打卡異動、加班、審核或訂餐歷史時保留人員歷史，後端拒絕刪除。
2. 可刪除時，Supabase Auth 與 `set_employee` 必須在同一交易一致完成。
3. 系統永遠保留至少一位有效管理員。
4. 主管或管理員刪除自己時需再次驗證目前密碼，完成後立即登出。

權限：

### 3.3.7 國定假日與週期設定

1. 國定假日保存日期、名稱與排序。
2. 週期設定包括：
   - 八週起算日。
   - 每週起算日。
   - 每月起算日。
3. 班表預設顯示今天所在的八週週期，依起算日每 56 天前後推算。
4. 主管與管理員可維護週期與國定假日。
5. 匯出期間依「每月起算日」切分；例如每月起算日為 26 日，每期為上月 26 日至本月 25 日。
6. 三種班表匯出視窗的預設值一律使用「今天所在期間的上一期」。
7. 例如每月起算日為 26 日：
   - 今天是 7 月 28 日時，預設為 6 月 26 日至 7 月 25 日。
   - 今天是 7 月 25 日時，預設為 5 月 26 日至 6 月 25 日。
8. 使用者可在匯出前自行修改開始日期與結束日期，開始日期不得晚於結束日期。
9. 每月起算日為 29、30 或 31，而月份沒有該日期時，該月以最後一日作為起算日。

### 3.3.8 自動排班與例休檢查

自動排班採「先預覽、再套用」：

1. 使用在職期間。
2. 使用可支援單位順序。
3. 使用可排班班別順序。
4. 使用班別需求人數。
5. 使用固定休假星期與每月休假天數。
6. 檢查例假、休息日與連續上班。
7. 預覽不立即寫入。
8. 套用預覽後才批次保存。
9. 可取消預覽。

例休檢查依目前八週範圍，顯示每位人員的缺漏與待確認項目。

權限：

- **員工：** 可查看套用後的完整班表。
- **主管：** 具備員工全部能力，並可執行預覽、套用、取消與例休檢查。
- **管理員：** 具備主管全部能力。

### 3.3.9 排序共通規格

以下設定最前方統一有拖曳圖示：

1. 人員。
2. 單位。
3. 班別。
4. 假別。
5. 班表加班。
6. 訂餐商品。

共通規則：

- 資料列本身不作為拖曳把手。
- 只有最前方圖示可開始拖曳。
- 放開後立即更新畫面。
- 儲存後重新整理與重新登入仍維持順序。
- 一般設定頁拖曳欄約 30px，圖示約 22×26px。
- 訂餐商品依其表格版面使用較大的操作區。

# 第四章　紀錄頁

## 4.1 頁面目的

紀錄頁集中提供個人歷史查詢，以及管理員專用的加班審核與打卡管理。訂餐統計放在訂餐頁，不放在紀錄頁。

## 4.2 分頁

1. **個人記錄：** 所有已登入角色查看自己的班表、打卡、異常、加班與訂餐歷史。
2. **加班審核：** 管理員查詢、調整、核准、退回、批次處理與代為申請。
3. **打卡管理：** 管理員查詢異常、補登或修改打卡並查看異動歷程。

### 4.2.1 個人記錄

#### A. 查詢與按鈕

1. 日期起日。
2. 日期迄日。
3. 使用者變更開始日期或結束日期後，立即重新查詢並更新表格。
4. 本分頁不顯示查詢按鈕。
5. 上一頁。
6. 下一頁。
7. 每頁 50 筆。
8. 可查詢全部歷史，不限最近 30 天。
9. 不顯示操作欄。

#### B. 顯示欄位

依序顯示：

1. 日期。
2. 圖示。
3. 班別。
4. 打卡時間。
5. 異常。
6. 加班。
7. 打卡備註。
8. 加班備註。
9. 訂餐。

#### C. 圖示欄規則

1. 直接重現班表同一天的格子內容。
2. 顏色、文字顏色、圓角、字級與分段方式與班表一致。
3. 同一天有多種資料時依序上下疊加：
   - 班別。
   - 假別。
   - 加班。
4. 最多三個分段。
5. `0047 休息日` 與班別同時存在時沿用班表灰色文字規則。
6. 沒有班別、假別與加班時保持空白。

#### D. 打卡時間欄規則

上班與下班合併為單一欄，分兩行顯示：

```text
07:58 莊敬
11:25 莊敬
```

1. 第一行：上班時間及單位。
2. 第二行：下班時間及單位。
3. 缺少其中一筆時該行顯示 `-`。
4. 時間以 `Asia/Taipei` 顯示。
5. 個人頁只顯示必要的時間、單位與狀態，不顯示原始 GPS、精準度、距離或 IP。

#### E. 加班、異常與訂餐

1. 加班欄顯示狀態與總時數。
2. 異常欄可同時顯示多種即時計算異常。
3. 打卡備註、加班備註分欄顯示。
4. 訂餐例如：`雞腿×1、排骨×2`。
5. 訂餐文字使用醒目粉紅樣式。
6. 訂餐所依據的上班卡被清除時顯示警告。

#### F. 權限

- **員工：** 可查詢自己的個人歷史記錄。
- **主管：** 具備員工全部能力。
- **管理員：** 具備主管全部能力。

### 4.2.2 加班審核

#### A. 查詢、按鈕與分頁

1. 日期起日。
2. 日期迄日。
3. 人員。
4. 狀態：待審、核准、退回、全部。
5. 日期、人員或狀態變更後，立即重新查詢並更新審核清單。
6. 本分頁不顯示查詢按鈕。
7. 代為申請。
8. 批次核准。
9. 批次退回。
10. 全選核取方塊與逐筆核取方塊。
11. 上一頁、下一頁。
12. 每頁 20 筆。

#### B. 表格欄位

依序顯示：

1. 勾選。
2. 日期。
3. 員工姓名。
4. 班別名稱與班表上下班時間。
5. 打卡時間。
6. 加班時數。
7. 備註。
8. 狀態。
9. 操作。

版面：

- 勾選欄寬約 40px，左右保留少量空間。
- 日期欄寬約 112px，警告顯示於日期下方。
- 狀態欄寬約 62px。
- 操作欄允許按鈕換行。

加班時數格式：

```text
提早＋延後=合計
2＋0.5=2.5
```

#### C. 操作邏輯

1. **調整**
   - 修改提早時數。
   - 修改延後時數。
   - 修改員工加班備註。
   - 儲存為待審。

2. **核准**
   - 將申請設為核准。

3. **退回**
   - 將申請設為退回。
   - 退回原因可留空。

4. **批次核准／退回**
   - 依勾選項目處理。
   - 執行前再次確認。

5. **代為申請**
   - 選擇人員與日期。
   - 輸入提早、延後與備註。
   - 可建立待審。
   - 可建立並直接核准。

6. 時數不得為負數，必須是 0.5 的倍數，可為 0。
7. 打卡異動後：
   - 狀態回待審。
   - 原時數保留。
   - 顯示「打卡時間已異動」。
   - 再次核准或退回後清除警告。
8. 班表異動不改變既有申請。
9. 每次審核與時數調整寫入審核歷程。

#### D. 權限

- **員工：** 可在打卡頁與個人記錄查看自己的申請狀態。
- **主管：** 具備員工全部能力。
- **管理員：** 具備主管全部能力，並可查看所有人的申請、調整、核准、退回、批次處理及代為申請，包含處理自己的申請。

### 4.2.3 打卡管理

#### A. 查詢與按鈕

1. 日期起日。
2. 日期迄日。
3. 人員。
4. 異常類型。
5. 只顯示異常。
6. 日期、人員、異常類型或「只顯示異常」變更後，立即重新查詢並更新清單。
7. 本分頁不顯示查詢按鈕。
8. 上一頁、下一頁。
9. 每頁 50 筆。
10. 編輯。
11. 歷程。

#### B. 表格欄位

1. 日期。
2. 員工姓名與工號。
3. 班別與班表時間。
4. 上班時間與單位。
5. 下班時間與單位。
6. 異常。
7. 每日打卡備註。
8. 操作。

#### C. 編輯視窗

可修改：

1. 上班時間。
2. 上班單位。
3. 下班時間。
4. 下班單位。
5. 每日打卡備註。
6. 本次異動原因；此欄選填並保存於歷程。

可用於：

- 補登上班。
- 補登下班。
- 修改時間。
- 修改單位。
- 清除時間。

儲存後重新計算異常，並依規則把相關加班申請改回待審。

#### D. 歷程

顯示：

1. 操作時間。
2. 欄位或操作類型。
3. 原值。
4. 新值。
5. 原因。
6. 操作人。

同時保存修改前與修改後完整 JSON 快照，供稽核使用。

#### E. 權限

- **員工：** 可在個人記錄查看自己的打卡顯示資料。
- **主管：** 具備員工全部能力。
- **管理員：** 具備主管全部能力，並可查詢全體打卡、查看原始稽核資料、補登、修改、清除與查看歷程。

## 4.3 其他相關規則

1. 個人記錄由 `personal-records-v2` Edge Function 讀取。
2. 個人記錄後端同時讀取班別、假別與班表加班，回傳圖示分段資料。
3. 加班審核清單由 `attendance-overtime-admin-list` 讀取。
4. 加班審核操作由 `attendance-overtime-admin-action` 處理。
5. 打卡管理清單由 `attendance-admin-list-v2` 讀取。
6. 打卡管理寫入及歷程由 `attendance-admin-action-v2` 處理。
7. 查詢結果依日期倒序顯示。
8. 任何管理員異動都需由後端再次驗證角色與帳號有效期間。

# 第五章　系統環境、資料庫與其他規格

## 5.1 章節目的

本章集中整理不屬於前四個頁面的共用規格，包括執行環境、程式語言、部署方式、登入與首頁、角色繼承、後端服務、資料庫結構、欄位中文說明、安全、稽核、驗收與版本範圍。

## 5.2 執行環境與使用技術

### 5.2.1 前端

- 型態：瀏覽器靜態網站。
- 原始碼：`src/renderer/`。
- GitHub Pages 發佈目錄：`docs/`。
- 語言：HTML5、CSS3、原生 JavaScript。
- Excel：ExcelJS 4.4.0。
- 頁面設計：手機優先，支援桌面與平板。
- 正式資料來源：Supabase，不使用舊 JSON 文件作為正式儲存。

### 5.2.2 後端

- 平台：Supabase。
- 身分驗證：Supabase Auth。
- 資料庫：PostgreSQL。
- API：Supabase REST、PostgreSQL RPC、Supabase Edge Functions。
- Edge Functions 語言：TypeScript。
- Edge Functions 執行環境：Deno／Supabase Runtime。
- 後端函式使用 `@supabase/server` 的身分驗證包裝。

### 5.2.3 開發與發佈

- Node.js 用於本機預覽、檢查與發佈腳本。
- 主要指令：

```text
npm run web
npm run web:check
npm run web:publish
npm run v2:check
```

- `npm run web`：啟動本機靜態預覽。
- `npm run web:check`：檢查公開 Supabase 設定。
- `npm run web:publish`：將 `src/renderer/` 同步到 `docs/` 並更新資源版本。
- `npm run v2:check`：檢查 V2 檔案與發佈版本對齊。
- 前端修改完成後，`src/renderer/` 與 `docs/` 必須同步。
- 正式程式碼與規格書由 GitHub `main` 分支管理。

## 5.3 登入、首頁與帳號規則

### 5.3.1 未登入

1. 登入介面使用全畫面。
2. 未登入不顯示班表、員工、打卡、加班與訂餐資料。
3. 敏感資料不得先載入後只用 CSS 隱藏。

### 5.3.2 登入後首頁

顯示：

- 使用者姓名。
- 使用者角色。
- 大型打卡入口。
- 班表入口。
- 訂餐入口。
- 紀錄入口。
- 修改密碼。
- 登出。

手機版：

1. 修改密碼與登出在姓名右側靠右。
2. 四個主入口採精簡尺寸，文字置中。
3. 打卡、訂餐、紀錄頁的返回首頁使用 X 圖示。

Android 返回鍵：

1. 有可關閉視窗時關閉視窗。
2. 沒有視窗時回首頁。
3. 已在首頁時保持首頁。

### 5.3.3 角色繼承

- **員工 `employee`：** 使用自己的打卡、加班申請、訂餐與個人記錄，並查看完整班表。
- **主管 `manager`：** 包含員工全部權限，另管理班表、一般單位、人員非角色資料、商品、截止時間、補助、訂餐統計與匯出。
- **管理員 `admin`：** 包含主管全部權限，另管理角色、管理員帳號、單位打卡設定、全體打卡、稽核資料與加班審核。

### 5.3.4 任職有效期間

帳號有效期間：

```text
到職日 00:00
至離職日後第 5 日 23:59
```

1. 沒有離職日代表持續有效。
2. 到職日在未來時尚未生效。
3. 帳號停用、刪除或超過有效期間後，下一次受驗證操作由後端拒絕並清除登入狀態。
4. 最後一位有效管理員受到資料庫或後端交易保護。

### 5.3.5 Session

1. 手機：
   - 使用可跨關閉保留的儲存方式。
   - 48 小時滑動閒置期限。
2. 電腦、Android 平板、iPad、其他平板與觸控筆電：
   - 以分頁階段儲存為主。
   - 30 分鐘滑動閒置期限。
   - 關閉分頁或瀏覽器後需重新登入。
3. 裝置類型無法確認時以電腦規則處理。
4. 每次受驗證操作與使用者互動更新最後活動時間。
5. 閒置逾時後的第一個操作不得成功送出。

## 5.4 共用時間、權限與安全規則

1. 正式判定一律使用伺服器 `Asia/Taipei`：任職有效期間、打卡日期與時間、23:59 限制、加班申請期限、訂餐日期與截止時間、管理員操作時間。
2. 前端顯示可以使用瀏覽器格式化，但不得以使用者本機時間作為正式判定。
3. 所有角色、有效期間、打卡位置、截止時間、時數格式與歷史關聯都由後端或資料庫再次驗證。
4. 固定 IP、原始 GPS、精準度與距離只供管理員及後端服務使用。
5. 一般員工與主管只取得執行功能所需的最少資料。
6. 寫入操作使用 RLS、Edge Function、RPC 或 Service Role 的適當組合。
7. 任何前端隱藏按鈕都不是唯一權限控制。

## 5.5 後端服務、RPC 與交易

### 5.5.1 主要 Edge Functions

- `attendance-clock`：今日打卡狀態、上班打卡、下班打卡、GPS／IP 驗證。
- `attendance-overtime-employee`：員工加班日期、狀態、送出與刪除。
- `attendance-overtime-admin-list`：管理員加班審核清單。
- `attendance-overtime-admin-action`：審核、調整、批次處理與代為申請。
- `meal-order`：今日訂餐狀態、儲存與設定。
- `meal-report-v2`：訂餐統計。
- `meal-cancel-v2`：取消今日訂餐。
- `personal-records-v2`：個人記錄。
- `attendance-admin-list-v2`：打卡管理清單。
- `attendance-admin-action-v2`：打卡補登、修改與歷程。
- `member-auth-admin`：人員帳號建立、更新、重設密碼與刪除。
- `member-order-v2`：人員排序讀取與保存。
- `department-attendance-v2`：管理員讀取單位敏感打卡設定。

### 5.5.2 主要 RPC

- `save_schedule_entries_bulk(entries jsonb)`：批次保存班表格。
- `save_attendance_clock(...)`：原子保存上班或下班打卡。
- 單位打卡欄位、人員排序、訂餐與管理異動依正式 migration 定義使用 RPC 或交易函式。

### 5.5.3 必須具備交易一致性的操作

1. 上班與下班打卡。
2. 管理員修改打卡並重設加班狀態。
3. 新增、修改與取消整張訂單。
4. 商品價格同步更新今日訂單。
5. 批次加班審核。
6. 帳號與 Auth 資料刪除。
7. 最後一位管理員保護。
8. 批次班表保存。

任一步驟失敗時，不留下部分完成資料。

### 5.5.4 冪等性

以下相同請求重送時不得建立重複資料或改寫第一次有效結果：

- 上班打卡。
- 下班打卡。
- 新增與修改訂單。
- 送出加班申請。
- 批次審核。
- 批次班表保存。

## 5.6 資料庫共通規格

1. 資料庫：PostgreSQL。
2. 主鍵多數使用 UUID。
3. 時間戳使用 `timestamp with time zone`。
4. 日期使用 `date`。
5. 每日班表與打卡以 `Asia/Taipei` 工作日期對應。
6. 目前正式班表來源：`schedule_entries`。
7. 目前正式打卡來源：`attendance_records`。
8. 打卡異動歷程：`attendance_action_logs`。
9. 打卡加班申請：`attendance_overtime_requests`。
10. 加班審核歷程：`overtime_review_logs`。
11. 訂餐商品、設定與訂單：`meal_products`、`meal_settings`、`meal_orders`。
12. 舊 JSON 文件不再作為正式資料來源。
13. 舊的 `attendance_logs` 與 `clock_locations` 已於 2026-07-08 移除；正式打卡流程只使用 `attendance_records` 與 `set_departments` 的打卡設定。
14. 外鍵與唯一限制用來保護歷史關聯及每日唯一資料。
15. 資料表名稱與欄位採英文 snake_case；本規格提供中文意義。

登入：

- 手機使用 48 小時滑動閒置。
- 平板與電腦使用 30 分鐘滑動閒置。
- 超過任職有效期間後，第一個受驗證操作被拒絕。

打卡：

- 手機 GPS 299 公尺且精準度 299 公尺可通過。
- 301 公尺或精準度 301 公尺時改驗證 IP。
- 電腦不要求 GPS。
- 無上班卡仍可打下班卡。
- 重複請求不改寫第一次時間。

加班：

- 提早 29 分鐘不產生 0.5 小時。
- 提早 30 分鐘產生 0.5 小時。
- 第五日 23:59 前可申請。
- 打卡異動後回待審但時數不變。
- 調整視窗可修改時數與備註。
- 批次操作前有確認。

訂餐：

- 無上班卡時不建立訂單。
- 無班表但有上班卡可訂餐。
- 首次全部 0 不建立訂單。
- 已有訂單全部改 0 需確認。
- 數量只接受 0 或正整數。
- 停用品項只可減少或取消。
- 截止後停止新增、修改與取消。
- 上班卡清除後訂單保留並顯示警告。

班表：

- 所有登入角色可看完整班表。
- 主管及管理員可編輯。
- 人員、單位、班別、假別、加班與訂餐品項排序在重新整理後保留。
- 個人記錄圖示與班表同日內容、順序與顏色一致。

# 第六章　介面樣式統一規格

## 6.1 章節目的與適用範圍

本章定義福圓號排班系統所有頁面與彈出視窗的共用介面樣式。目的如下：

1. 讓打卡、訂餐、班表、紀錄、設定及管理介面維持一致的視覺與操作方式。
2. 統一表格、按鈕、頁籤、下拉選單、日期／時間輸入框、一般輸入框、多行文字框、核取方塊、卡片與彈出視窗的高度、圓角、配色、間距及狀態回饋。
3. 減少重複 CSS、互相覆蓋與 JavaScript 動態注入樣式。
4. 新增功能時優先重用共用元件，不為單一頁面重新建立外觀近似但規格不同的樣式。
5. 保持手機優先，同時支援平板與電腦。

本章適用於：

- 登入頁與登入後首頁。
- 打卡頁及加班申請區。
- 訂餐頁、訂餐設定與訂餐統計。
- 班表頁導覽、工具列與設定視窗。
- 紀錄頁、加班審核、打卡管理與編輯打卡視窗。
- 單位、人員、班別、假別、加班及其他設定視窗。
- 後續新增的所有前端頁面與元件。

## 6.2 CSS 檔案分工與載入順序

### 6.2.1 檔案職責

1. **`styles.css`**
   - 保存網站基礎版面、既有頁面結構與班表主要格線樣式。
   - 不再新增可由共用設計系統處理的輸入框、按鈕、表格或彈窗重複規則。

2. **`v2-schedule-nav.css`**
   - 只處理班表導覽列、首頁按鈕、歷程按鈕及班表導覽的特殊排版。
   - 不作為一般表單或一般按鈕的樣式來源。

3. **`ui-system.css`**
   - 為全系統共用介面樣式的正式來源。
   - 集中保存設計變數、表單控制項、按鈕、頁籤、表格、卡片、區塊、彈出視窗、拖曳控制與響應式規則。
   - 必須在 `styles.css` 與 `v2-schedule-nav.css` 後載入，使共用規格可收斂舊樣式差異。

### 6.2.2 載入與同步

1. 正式載入順序：

```text
styles.css
v2-schedule-nav.css
ui-system.css
```

2. `src/renderer/` 與 `docs/` 必須有相同的 CSS 檔案與內容。
3. 修改共用 CSS 後必須更新靜態資源版本參數，避免瀏覽器沿用舊快取。
4. 一般元件樣式不得由 JavaScript 建立 `<style>` 標籤或動態注入整段 CSS。
5. JavaScript 只可依資料設定必要的動態值，例如班別、假別、加班的背景色與文字色。
6. 模組專用版面若無法共用，仍應寫入 `ui-system.css` 的明確區段，不得散落在多個 JavaScript 檔案。

## 6.3 共用設計變數

### 6.3.1 尺寸與圓角

正式共用變數如下：

| 項目 | 變數 | 標準值 |
|---|---|---:|
| 一般控制項高度 | `--ui-control-height` | 40px |
| 精簡控制項高度 | `--ui-control-height-compact` | 34px |
| 一般控制項圓角 | `--ui-control-radius` | 12px |
| 圖示按鈕圓角 | `--ui-icon-radius` | 10px |
| 表格外框圓角 | `--ui-table-radius` | 14px |
| 內容區塊圓角 | `--ui-section-radius` | 18px |
| 頁面卡片及彈窗圓角 | `--ui-page-radius` | 24px |

手機寬度不超過 640px 時，一般控制項高度調整為 42px，以增加觸控操作面積。

### 6.3.2 配色

1. 共用介面沿用系統暖色系主題。
2. 正式共用變數至少包含：
   - `--ui-surface`：主要表面底色。
   - `--ui-surface-raised`：輸入框、表格列與浮起元件底色。
   - `--ui-surface-muted`：表頭與次要區域底色。
   - `--ui-surface-hover`：可操作元件滑鼠經過底色。
   - `--ui-border`：一般邊框。
   - `--ui-text`：主要文字。
   - `--ui-muted`：次要文字。
   - `--ui-accent`：主要操作色。
   - `--ui-accent-strong`：主要操作深色。
   - `--ui-danger`：錯誤、危險與刪除提示色。
   - `--ui-focus-ring`：鍵盤或輸入聚焦外框。
   - `--ui-row-hover`：表格列滑鼠經過底色。
3. 不得在功能頁任意新增近似的米色、棕色或灰色；需新增顏色時先增加具語意的共用變數。
4. 班別、假別與班表加班顏色屬於業務資料，可依設定值動態顯示，不受固定主色限制。

## 6.4 表單控制項

### 6.4.1 適用元件

共用表單規格適用於：

- 一般文字輸入框。
- 數字輸入框。
- 密碼輸入框。
- 日期輸入框。
- 時間輸入框。
- 下拉選單。
- 多行文字框。
- 核取方塊與單選按鈕。

### 6.4.2 一般輸入框、日期、時間與下拉選單

1. 一般高度為 40px，手機為 42px。
2. 圓角為 12px。
3. 邊框使用 `--ui-border`。
4. 背景使用 `--ui-surface-raised`。
5. 文字使用 `--ui-text`。
6. 左右內距原則上為 12px。
7. 相同表單列中的文字框、日期、時間與下拉選單必須等高。
8. `form-row` 內的控制項預設占滿可用寬度。
9. 日期與時間輸入框需維持瀏覽器原生操作能力，不以自製文字框取代。
10. 下拉選單不得因頁面不同而使用不同高度或不同圓角。

### 6.4.3 狀態回饋

1. **滑鼠經過：** 邊框略為加深。
2. **聚焦：** 使用主色邊框與 `--ui-focus-ring`，不得只依顏色極小變化表示聚焦。
3. **停用或唯讀：** 使用較淡背景與文字，取消陰影並顯示不可操作游標。
4. **格式錯誤：** 使用 `--ui-danger` 邊框，並搭配可理解的錯誤訊息。
5. 不得用移除 `outline` 而未提供替代聚焦樣式的方式美化控制項。

### 6.4.4 多行文字框

1. 預設最小高度為 88px。
2. 行高約 1.5。
3. 預設允許垂直調整高度。
4. 編輯打卡視窗的每日打卡備註最小高度為 96px。
5. 若功能限定單行，需使用明確的單行元件規格，不得以高度不一致的多行框替代。

### 6.4.5 核取方塊與單選按鈕

1. 顯示尺寸為 18px × 18px。
2. 使用系統主色作為 `accent-color`。
3. 標籤與控制項之間需保留至少 8px 間距。
4. 控制項與文字都應可點選；不得只讓極小方框可操作。

## 6.5 按鈕與操作元件

### 6.5.1 按鈕類型

1. **主要按鈕**
   - 使用 `.primary-btn` 或 `.btn-primary`。
   - 用於儲存、送出、確認、核准與主要下一步。
   - 使用主色至深主色漸層與白色文字。

2. **次要按鈕**
   - 使用 `.ghost-btn`、`.nav-btn` 或 `.btn-cancel`。
   - 用於返回、取消、查詢、匯出、調整及次要操作。
   - 使用白色或共用表面底色、共用邊框與主要文字色。

3. **精簡按鈕**
   - 加上 `.compact-btn`。
   - 高度為 34px，手機仍需保持可操作性。
   - 適用於表格操作、篩選列及密集工具列。

4. **圖示按鈕**
   - 使用共用圖示按鈕或設定圖示按鈕規格。
   - 圓角為 10px；需要完全圓形時必須有明確功能理由，例如首頁圓形圖示按鈕。
   - 必須提供 `title`、`aria-label` 或可理解文字。

### 6.5.2 共通外觀與行為

1. 一般文字按鈕高度為 40px。
2. 一般圓角為 12px，不再以所有文字按鈕一律使用 999px 膠囊形。
3. 文字按鈕字級原則上為 14px、粗體。
4. 左右內距原則上為 14px。
5. 同一列按鈕需垂直置中並使用一致高度。
6. 滑鼠經過時可微幅上移並增加陰影，但不得造成版面跳動或位移過大。
7. 停用按鈕需降低透明度、取消位移效果及陰影，並顯示不可操作游標。
8. 主要動作與危險動作不得只靠按鈕位置區分。
9. 刪除、清除或取消整張訂單等不可逆操作必須先確認。

## 6.6 表格

### 6.6.1 一般資料表格

適用於紀錄、訂餐設定、訂餐統計、加班審核、打卡管理與歷程等一般資料表格。

1. 表格外層必須使用共用包裝容器。
2. 外框邊線使用 `--ui-border`。
3. 外框圓角為 14px。
4. 表頭背景使用 `--ui-surface-muted`。
5. 表頭字級原則上為 13px、粗體。
6. 表頭高度不得低於 42px。
7. 一般資料列高度不得低於 44px。
8. 儲存格水平內距原則上為 12px。
9. 最後一列不顯示多餘的底線。
10. 滑鼠經過資料列時使用 `--ui-row-hover`。
11. 表格寬度超過容器時由外層水平捲動，不得讓整個頁面水平溢出。
12. 空資料狀態應在表格內顯示清楚文字，不得留下完全空白區塊。

### 6.6.2 欄寬與操作欄

1. 固定欄寬只用於勾選、日期、狀態、價格、啟用、圖示與操作等確實需要固定寬度的欄位。
2. 名稱、備註及說明欄優先使用剩餘寬度。
3. 操作欄按鈕可在空間不足時換行，但不可超出表格外框。
4. 訂餐設定表格需保留拖曳、名稱、價格、啟用與操作欄完整可見。
5. 表格中的輸入框仍使用共用表單控制項規格，不得另外縮成不同高度。

### 6.6.3 班表例外

1. 班表主表格為高密度排班格，不直接套用一般資料表格的列高與滑鼠經過規格。
2. 班表格線、凍結欄、八週日期欄、分段顏色與拖曳選取由班表專用 CSS 控制。
3. 班表外框與導覽控制仍需沿用共用色彩及圓角變數，除非技術上為了連續格線需使用局部 0 圓角。

## 6.7 頁籤、卡片、區塊與彈出視窗

### 6.7.1 頁籤

1. 今日訂餐、訂餐統計、訂餐設定及紀錄頁各分頁使用相同頁籤外觀。
2. 頁籤群組使用共用外框、12px 圓角與內距。
3. 未選取頁籤使用透明或次要表面底色。
4. 選取頁籤使用 `--ui-accent` 背景與白色文字。
5. 頁籤文字不得因選取狀態改變高度或造成群組跳動。

### 6.7.2 頁面卡片與內容區塊

1. 首頁、打卡、訂餐、紀錄、班表主卡片及登入卡片使用 24px 圓角。
2. 卡片內的次級內容區塊使用 18px 圓角。
3. 同一層級區塊的邊框、底色與陰影需一致。
4. 不得在同一頁面同一層級任意混用 16、18、22、24、26、28px 等多種圓角。
5. 卡片與區塊應使用共用表面色，業務狀態提示才可使用成功、警告或錯誤底色。

### 6.7.3 彈出視窗

1. 一般彈出視窗使用 24px 圓角。
2. 標題區、內容區與底部操作區需有一致間距。
3. 標題區與底部操作區使用淡色分隔線。
4. 底部主要按鈕放在靠右位置；取消按鈕位於主要按鈕之前。
5. 內容過高時只讓內容區捲動，標題與主要操作應保持可辨識。
6. 彈窗不得因內部表格或長文字突破螢幕寬度。
7. 編輯打卡視窗使用 `.attendance-edit-modal`：
   - 電腦最大寬度約 560px。
   - 上班時間、上班單位、下班時間、下班單位在足夠寬度時使用兩欄。
   - 手機改為單欄。
   - 時間輸入框、下拉選單、備註框、取消與儲存按鈕都使用本章共用規格。

## 6.8 響應式與無障礙規格

### 6.8.1 響應式

1. 系統以手機優先設計。
2. 寬度不超過 640px 時：
   - 一般控制項高度為 42px。
   - 兩欄表單改為單欄。
   - 彈窗外圍留白縮為約 12px。
   - 彈窗最大高度不得超過視窗高度扣除外圍留白。
3. 表格無法完整顯示時使用表格容器水平捲動。
4. 篩選列與按鈕列允許換行，不得因強制單行造成整頁水平溢出。
5. 主要操作按鈕在手機上需有足夠點擊範圍，不得僅保留小型文字連結。

### 6.8.2 鍵盤與可辨識性

1. 所有可操作元件必須可透過鍵盤取得焦點。
2. 聚焦狀態必須清楚可見。
3. 圖示按鈕必須提供可存取名稱。
4. 文字與背景需保持足夠對比。
5. 狀態不可只靠顏色表示，錯誤、警告、停用與已選取狀態需搭配文字、圖示、邊框或形狀差異。
6. 表單標籤應對應輸入元件；無法使用 `for` 時也需讓控制項與文字的關係清楚。
7. 動畫與滑鼠位移效果應簡短，不得妨礙操作或造成明顯晃動。

## 6.9 開發與命名規則

1. 新增頁面前先確認現有共用類別是否可直接使用。
2. 一般輸入框、下拉選單、日期、時間與多行文字框不得為單一頁面重複定義完整外觀。
3. 一般按鈕優先使用：

```text
.primary-btn
.ghost-btn
.nav-btn
.btn-primary
.btn-cancel
.compact-btn
```

4. 一般表格優先使用：

```text
.records-table-wrap
.records-table
```

5. 表單排列優先使用：

```text
.form-grid
.two-col
.form-row
.form-row-wide
```

6. 頁面或功能確實需要差異時，以「共用類別＋功能專屬類別」組合，例如：

```text
.modal modal-form-compact attendance-edit-modal
```

7. 功能專屬類別只描述該功能必要的寬度、欄位排列或特殊限制，不重複共用邊框、圓角、字型與按鈕樣式。
8. 禁止為了快速修正而在 HTML 大量加入行內 `style`。
9. 動態業務顏色、位置或寬度計算可使用行內樣式；固定外觀必須放在 CSS。
10. 不得再於 JavaScript 建立 `<style>` 並注入整段固定 CSS。
11. CSS 類別名稱使用英文小寫與連字號，名稱需表達元件或用途，不使用無意義流水號。
12. 優先使用共用變數，不直接重複硬寫相同顏色、高度與圓角。
13. 修改舊元件時應逐步移除被 `ui-system.css` 取代的重複規則，避免長期只靠後載入覆蓋。
14. 不可為統一外觀而破壞功能專用版面，例如班表凍結欄、拖曳排序與高密度操作格。

## 6.10 特殊元件與例外

以下元件可保留特殊尺寸或形狀，但仍需沿用共用配色、聚焦、停用與響應式原則：

1. 首頁大型功能入口。
2. 打卡頁大型上班與下班按鈕。
3. 班表彩色班別、假別與加班按鈕。
4. 班表主表格、凍結欄、週次導覽與日期格。
5. 復原、重做、返回首頁等純圖示按鈕。
6. 拖曳排序把手。
7. 顯示業務狀態的成功、警告與錯誤區塊。

例外規則：

- 特殊元件必須有明確操作或資訊密度理由。
- 不得只因為位於不同頁面就建立新的高度、圓角或配色。
- 特殊元件的鍵盤焦點、停用狀態與觸控面積仍須符合本章規格。

## 6.11 驗收標準

### 6.11.1 視覺一致性

1. 編輯打卡視窗的時間輸入框、下拉選單、備註框、取消與儲存按鈕都有一致圓角與高度。
2. 訂餐設定、打卡管理、加班審核及個人記錄的表格外框、表頭與資料列風格一致。
3. 同類型按鈕在不同頁面高度、字級、圓角與配色一致。
4. 日期、時間、數字、文字與下拉選單在同一表單列中等高。
5. 頁籤選取狀態在訂餐頁與紀錄頁一致。
6. 同一層級卡片或區塊不再出現無理由的多種圓角。

### 6.11.2 操作與響應式

1. 手機版編輯打卡視窗為單欄，所有欄位與按鈕完整顯示。
2. 手機版主要控制項點擊高度至少 42px；精簡表格按鈕仍需可準確操作。
3. 鍵盤操作時所有表單與按鈕都有清楚焦點。
4. 停用、錯誤與唯讀狀態可明確辨識。
5. 一般資料表格在窄螢幕由容器捲動，不使整頁水平溢出。
6. 班表專用格線、凍結欄、拖曳與排班操作不得因共用 CSS 失效。

### 6.11.3 程式結構

1. `ui-system.css` 為一般共用元件樣式的唯一正式來源。
2. 已整併模組不得重新加入 JavaScript 動態固定 CSS。
3. `src/renderer/ui-system.css` 與 `docs/ui-system.css` 內容一致。
4. 新增共用樣式後需更新資源版本參數。
5. 發佈前需執行 JavaScript 語法檢查與主要頁面人工驗收。
6. 後續重構舊 `styles.css` 時，必須以不改變既有功能為前提，分批移除已被共用樣式取代的重複規則。
